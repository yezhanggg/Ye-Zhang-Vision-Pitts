# Architecture review (agent C) — Sat 2026-09-26 ~19:25 ET

Read-only pass over `app/`, `src/visionpitts/`, `scripts/`, `supabase/`. Production build, sourcemap attribution and Playwright 1.63 runs were done in the scratchpad; the repo, `app/dist` and `export/` are untouched. Every number below is measured unless marked *estimate*.

**Good:** one honest data contract (`TractProps` in `app/src/lib/types.ts` is exactly what `properties()` in `src/visionpitts/export.py` writes), a pure scoring function mirrored in Python with a shared parity fixture, a URL hash that already round-trips the whole state (`app/src/lib/hash.ts`, 10 tests), and Explore's bundled-first / Supabase-swap loader (`app/src/lib/explore/remote.ts`) is the right shape for a file that must open by double-click.

## 1. Structure

**Flow.** `data/raw` → `scripts/01–08` → `data/interim/*.parquet` + `data/processed/*` → `export.write_all()` writes 19 files to `app/src/data/` (3,740,573 B tracked) → `lib/data.ts` and `lib/explore/catalog.ts` inline every file with `import.meta.glob(..., query: '?raw')` and `JSON.parse` it at module load → zustand `AppState` (`lib/store.ts`) → `lib/derived.ts` memoizes `allResults(weights)` per weights object → `lib/paint.ts` → `components/MapView.tsx` pushes values through `setFeatureState` (350 ms tween). Explore hides the built-in tract layers and drives `overlays[]` from `useGeo`/`useVariable`. The export is the same bundle with `vite-plugin-singlefile` (`app/vite.config.ts`, mode `export`).

**Brittle.**
- `MapView.tsx` (891 lines) owns intro, terrain, contours, overlays, sync, pins, orbit. Three instances live per session (landing hero, Explore, Analysis; two at once in Compare tracts), each re-sending the 2.4 MB buildings GeoJSON to its own worker. `AnimatePresence mode="wait"` in `App.tsx` and `AnalysisView.tsx` destroys and rebuilds the map on every Explore↔Analysis switch: measured 1.0–4.7 s from clicking "Analysis" to the map being ready.
- First paint after "Open VisionPitts" waits for map construction. In-page trace: landing gone at 0.5–0.6 s (GPU), then one synchronous long task of 0.5–1.85 s (`map.remove()` of the hero + `new maplibregl.Map` + `setup()`), Explore map ready at 1.1–2.6 s (GPU) or 3.5–5.3 s (SwiftShader). In every run "Layers" became visible at the same instant as the map (3,785 vs 3,790 ms; 3,500 vs 3,502 ms): the click is a discrete event, React flushes the effect, and the memoized `Promise.all([loadBasemapStyle(), loadDemConfig()]).then` runs before the browser paints the rail. The judge sees a frozen fade for 1–5 s.
- `data.ts` and `catalog.ts` turn a missing or unparsable JSON into an empty fallback with only `console.warn`; a broken export ships as a silently empty app. Nothing checks that `scoring.factors[].id` exist on the tracts or that `focus.json` GEOIDs resolve.
- Two hand-synchronised unions: `Level`/`LayerId` in `store.ts` vs `BrowseLevel`/`LayerKey` in `explore/types.ts`.
- `LAYER_ROWS` in `lib/explore/copy.ts` hardcodes "128 city tracts / 314 block groups / 32 ZCTAs" while the online scope is 394 / 1,062 / 170. `app/vercel.json` sets Cache-Control for `/data/(.*)`, a path that no longer exists (`app/public` is empty; data is inlined).
- `remote.ts` `markUnavailable()` poisons the whole session on the first failed request, and `restGet` (`lib/supabase.ts`) has an 8 s budget across pages; county block groups need two pages (1,062 rows > `PAGE_SIZE` 1000), so one slow page silently downgrades Explore to the city subset for the rest of the session with a `console.info` and a smaller number in the scope chip.
- `MapView` creates the map only after both the basemap style (7 s timeout) and the DEM TileJSON (4 s) resolve; on a network that blocks openfreemap.org the judge stares at "Loading map…" for 7 s before the grey fallback appears. Tile failures after that are filtered out of `map.on('error')` with no visible notice.

**Bundle** (production build, sourcemap attribution; `assets/index-*.js` 5,400,282 B raw / 983,045 B gzip; CSS 119,108 B / 19,343 gz; `export/index.html` 5,519,532 B). One chunk, no code-splitting (the export cannot have any). `?raw` inlining adds no escaping overhead (2,473,909 B in bundle vs 2,473,903 on disk).

Reading: the 5.5 MB file parses in ~0.25 s. What the judge waits for is WebGL context + basemap/DEM fetch + the globe intro (`easeTo` 2.2 s + `flyTo` 5 s, tract fill hidden until it ends) + 5–16 MB of vector tiles, terrain tiles and fonts. The dev server is 15× slower to "Layers" than the build; never demo from it. SwiftShader adds ~2.4 s per map creation; a laptop with a real GPU is nearer the GPU figures. The 4 Supabase requests are geo_units for tract, bg (2 pages) and zcta.

**If the dataset doubles.** Scoring and paint are not the problem: `allResults` is 114 × 5 typologies × 6 factors per weights object, and the 350 ms tween issues at most one `setFeatureState` per tract per frame; 800 tracts is still sub-10 ms (*estimate*). `tracts.json` at 394 tracts ≈ 850 KB (*estimate*; properties dominate). County-wide block groups bundled: `acs_bg` ≈ 1.4 MB, `geo_bg` ≈ 450 KB (*estimate*). What breaks first is buildings: 46% of the file for 8 tracts; covering 128 tracts is ~16× (≈40 MB, *estimate*), the double-click file stops being shareable and three workers each index 150k footprints. Second: `restGet` paging with jsonb geometry (bg is already 2 pages against an 8 s budget). Third: `useGeo` in `ExploreView.tsx` fetches all five levels' county geometry on mount whether or not the layer is on.

## 2. Supabase

**Current state.** `0001_init.sql`: `acs_variables`, `geo_units` (jsonb geometry), `acs_values` (long), `dataset_versions`, all public-select under RLS, written only by `scripts/08_publish_supabase.py` with the secret key. `scenarios` exists with owner-scoped RLS and a realtime publication but needs Anonymous sign-ins enabled and has no UI or client code. Explore reads county rows when online and falls back to the bundle; Analysis is 100% bundled; the anon key ships in the bundle (by design, read-only); `file://` never contacts Supabase (`lib/supabase.ts` `detect()`).

**What moves next, what stays.** Move: a `tracts` table (the `TractProps` object as jsonb + geometry, keyed by `geoid`, stamped with `scoring_version`) so the hosted app can pick up a nightly pipeline run without `npm run export`; `scoring_configs` (versioned `config/scoring.json`); `scenarios` (already there); `policy_areas` (IZ / bonus / ADU polygons as jsonb); `sources` only if you want the registry queryable, otherwise it stays JSON. Explanations: keep the existing endpoint's cache in memory; a table is not worth a migration. Stays client-side forever: scoring, stability draws, ranking, flips, paint, point-in-polygon search; the bundled city subset as the fallback for everything. Never compute a score on the server: it would break parity with `src/visionpitts/scoring.py` and the offline file.

**What it enables that the file cannot.** Saved and shared scenarios with a short slug and a name/author/note (the hash link already carries the full state, so the slug is a convenience plus a listing, not a capability); planner accounts (magic link) and "my scenarios"; notes on tracts (`tract_notes`: geoid, body, owner, RLS insert-own); a public read-only API for CDCs (PostgREST already is one for Explore data; adding `tracts` exposes the scored inputs at `GET /rest/v1/tracts?select=geoid,props`); versioned scoring configs with a pin in the URL; nightly refresh without re-export (only for what lives in tables); preset telemetry (an insert-only `events` table: cheap, but a privacy line you do not need to cross this weekend).

**What it costs.** Online-only for every new feature; one extra round trip per click if you ever fetch per tract (today's design avoids that — keep bundling); anonymous auth to write (a dashboard toggle plus an `auth.users` row per device); a second deploy surface (`supabase db push`, loader reruns, RLS policies that fail at runtime, not in tests); the double-click demo can only degrade to the hash link; PostgREST's 1,000-row pages and your 8 s budget already bite on block-group geometry.

**Minimal next step (deltas on `0001_init.sql`).**
```sql
create table public.scoring_configs (version text primary key, config jsonb not null, published_at timestamptz not null default now());
create table public.tracts (
  geoid text primary key, name text not null, neighborhood text, residential boolean not null, focus text,
  props jsonb not null,                       -- exactly the TractProps object from tracts.json (contract: app/src/lib/types.ts)
  geom jsonb not null, scoring_version text not null references public.scoring_configs(version), built_at timestamptz not null);
create table public.policy_areas (id text primary key, kind text not null check (kind in ('iz','bonus','adu','other')), name text not null, geom jsonb not null, props jsonb not null default '{}');
alter table public.scenarios add column hash text not null default '';   -- encodeHash() output verbatim; the offline file opens it as #<hash>
alter table public.tracts enable row level security; alter table public.scoring_configs enable row level security; alter table public.policy_areas enable row level security;
create policy "public read tracts" on public.tracts for select to anon, authenticated using (true);  -- same for the other two; no write policies
create policy "insert own scenarios (anon)" on public.scenarios for insert to anon with check (owner = auth.uid());  -- anonymous sign-in gives a uid
```
Keys: `tracts.geoid` (11-digit string = `TractProps.GEOID`), `scenarios.slug` as the share key, `owner = auth.uid()`. PostGIS: not warranted. The client wants whole layers as GeoJSON straight into MapLibre, the only spatial op (address → unit) runs in the browser (`lib/geo.ts`), and county-wide is 394 rows. Reads: direct `select` under RLS for everything. Writes: one `security definer` RPC `save_scenario(name, hash, weights, is_public)` that stamps `owner` and `scoring_version` and returns `slug`, so the insert shape is fixed and rate-limitable; plain insert is acceptable for a first cut. Flip map: unchanged, client-side `flipsBetween(allResults(A), allResults(B))` in `lib/derived.ts`; with the table it becomes one `GET /rest/v1/tracts?select=geoid,props,geom` per session, swapped into `tractsFC` the way `useGeo` swaps geometry, and only if `scoring_version` equals the bundled one. Offline: the export keeps reading the same JSON; a `useTracts()` mirror of `remote.ts` returns the bundle first and swaps when rows arrive.

**Verdict: (b).** State it as the next step in the pitch and README, do not build it before Sunday. The hash link already answers "can I share this comparison", judges cannot tell a slug from a hash, and anonymous auth + RLS + share UI + offline degrade is runtime risk that no unit test covers. If forced, (a) is ~5 h: 0.5 migration + enable anon sign-in; 1.0 client sign-in and `saveScenario`/`loadScenario` in `lib/supabase.ts`; 2.0 Save/Share UI in `CompareScenariosView.tsx` and a `?s=<slug>` route in `hash.ts` that resolves to the stored hash; 1.0 file:// degrade (button hidden, hash link shown) and tests for the resolver; 0.5 README + Vercel env check.
